# 示例：《月亮在等你》57 秒竖屏 MV

这是用本 Skill 做完的**真实案例**，源码、分镜、歌词时间轴全部在此，可直接对照。

> **版本提示**：本目录是 **v1 专用实现**（四屏直接 import `Moon / Orbit / Backdrop`），画面只有月相 + 星点 + 轨道 + 光圈。当前骨架已升级为 `VisualStage` + 视觉预设系统，见 `references/visual-system.md`。这里保留作「时间轴与逐句校准」的答案对照，**不要拿它的 scenes/components 去覆盖新骨架**。

## 结果

| 项 | 值 |
|---|---|
| 成片 | 57.05 秒 / 1080×1920 / 30fps / h264+aac / 约 13 MB |
| 结构 | 前奏 10.8s + 主歌 18.2s + 副歌 21s + 尾奏 7s = 57s |
| 主意象 | 月相：峨眉 → 上弦 → 盈凸 → 满月 → 收回一弯 |
| 歌 | 用户在网页版生成的带人声 mp3，83.91 秒，BPM 92 |
| 画面 | 四屏全部由圆、SVG path、线、渐变、文字代码画出，零外部素材 |

静帧见 `../../assets/preview/frame-120.png`（前奏）、`frame-500.png`（主歌）、`frame-1100.png`（副歌）。

## 为什么这个案例值得看

**1. 时间不是猜的。** 歌经 ASR 转写实测：人声 10.8 秒起、主歌到 28.75 秒、副歌 28.95 秒起、55 秒后纯器乐尾奏。四段边界据此定为 10.8 / 18.2 / 21 / 7 秒。副歌人声 28.95 秒与画面 29 秒的入屏闪白天然重合。

**2. 长歌没有硬裁。** 歌 83.91 秒 > 60 秒，按常规做法应从第一句前 2 秒（8.8 秒）起播。但那样人声会整体提前 8.8 秒，四屏全错开。这里保留完整前奏，靠 Composition 57 秒自然截断 + 结尾 2 秒淡出，音轨未物理裁剪。判断和理由写在 `分镜.md`。

**3. 逐屏截图查出的两个问题都修了。**
- S1 歌名贴到月亮顶边 → 挪开 `top`。
- S3 十二字长句「缺了的那一半 只是光还没走」被浏览器硬折，末行只剩「走」→ 改成优先按歌词自带空格折行。

## 怎么跑（用当前骨架）

仓库**不带音频文件**（用户的歌版权归用户）。自备一首带人声的 mp3，然后：

```bash
# 在本仓库根目录执行
cd ../..
node scripts/scaffold.mjs /tmp/moon-demo --song 你的歌.mp3 \
  --lyrics examples/moon/歌词.txt --title "月亮在等你" --preset moon
cp examples/moon/歌词时间轴.json /tmp/moon-demo/
cd /tmp/moon-demo
# 把 src/content.ts 四段秒数改成 10.8 / 18.2 / 21 / 7
npm install --registry=https://registry.npmmirror.com
npx tsc --noEmit
npx remotion still src/index.ts Main out/check-S3.png --frame=1100
npx remotion render src/index.ts Main out/mv.mp4
```

**只复制 `歌词时间轴.json` 和四个秒数**，不要复制本目录的 `src/`。新骨架的画面由 `preset` 决定，四屏场景、舞台组件都不用改。

本目录的价值是**当答案对照**：`歌词时间轴.json` 的九句、四段秒数、逐句校准的判断依据，都是跑通的版本。要看更丰富的分层画面，参考工作区里的 `moon-mv-v2/`（v2 成片与分镜）。
